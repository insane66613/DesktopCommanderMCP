## Reconciliation and changes

#559 is equivalent to predecessor 8eedb52, adopted as 8c67950. Validation occurs before virtual-session execution or stdin writes. The regression now spies on the actual terminal write boundary and proves both blocked non-delivery and benign delivery without starting a REPL.

#566 is equivalent to predecessor 74a94e2, adopted as 5e07105. It bounds recursive substitution/subshell extraction at 20, propagates limit errors into fail-closed validation, and handles quoted assignment/export prefixes. The semantic follow-up also passes depth through the fork's cmd/pwsh wrapper path, bounds inline-guard wrapper recursion, and shares prefix tokenization across executable extraction and fork guards. Windows tokenization uses PowerShell escaping rather than treating backslashes in quoted paths as escapes.

#792 is ported from its two isolated commits. Literal single/double here-string content is skipped; expandable expressions are parsed with quote-aware parentheses and backtick escape parity; CRLF and subsequent statements remain supported. Recursive expressions consume the same depth limit. The inline interpreter scanner also skips inert here-string spans so apostrophes in source do not create false executable segments. Legacy PowerShell detection normalizes extracted executables rather than whole source, preserving escaped inert expansions while blocking obfuscated executable tokens.

No dependencies or fork configuration fields were changed. Existing security tests were extended, not replaced. Older broad predecessor dependency updates are excluded.
